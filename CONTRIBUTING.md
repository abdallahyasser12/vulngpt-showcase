# Contributing to the public showcase

Thank you for helping improve the public VulnGPT showcase.

This repository contains a static public-facing website and supporting documentation. It does not contain the proprietary scanning engine or production backend. Contributions should improve the clarity, accessibility, accuracy, or maintainability of the public showcase.

## Appropriate contributions

- Documentation corrections and clarifications.
- Accessibility and responsive-layout improvements to the static showcase.
- Broken-link, spelling, and navigation fixes.
- Improvements to diagrams and public-safe technical explanations.
- Reproducible reports about the public website itself.

## Before opening a change

1. Check whether an issue or pull request already covers the change.
2. Explain the user or reader problem.
3. Keep product capability statements aligned with [Claims and Messaging](CLAIMS.md).
4. Cite a public source or approved internal artifact for any new factual or performance claim.
5. Do not add secrets, credentials, customer information, internal infrastructure details, or proprietary implementation material.

## Content standards

- Prefer precise, qualified technical language over superlatives.
- Distinguish current private-beta availability from planned product direction.
- Do not invent customer names, testimonials, metrics, certifications, compliance status, integrations, or supported platforms.
- Explain the limits of benchmarks and evaluation results.
- Keep responsible-use guidance visible and accurate.
- Ensure screenshots are genuine, appropriately licensed, and clearly identified.

## Website standards

- Preserve responsive behavior and keyboard accessibility.
- Use semantic HTML and descriptive alternative text.
- Respect reduced-motion preferences.
- Avoid adding unnecessary tracking, external scripts, or third-party dependencies.
- Test navigation and links at desktop and mobile widths.

## Pull requests

Include:

- a concise description of the problem and proposed change;
- the affected audience and pages;
- screenshots for visual changes;
- the factual basis for new product claims;
- any known limitations or follow-up work.

Do not use public issues or pull requests to disclose security vulnerabilities. Follow [SECURITY.md](SECURITY.md) instead.

NovaSecLabs may decline changes that expose proprietary information or are inconsistent with the product's public claims policy.
